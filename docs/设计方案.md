# 竞搭（竞赛组队匹配平台）· 设计方案

> 最后更新：2026-10-10。各部分细节见：[问卷草案-v2.md](问卷草案-v2.md)、[数据库设计.md](数据库设计.md)。

## 1. 要解决的问题

现在找队友主要靠在 QQ 群、朋友圈里喊一声，信息很散，看不到对方会什么；队伍缺一个前端，不知道该去哪找；个人想参赛，又找不到愿意收人的队伍。

平台要做的是：把"谁会什么"和"哪个队缺什么"都结构化记录下来，再由系统负责推荐匹配，并说明推荐理由。

- **用户**：多所学校的大学生。
- **比赛范围**：能在综测里加分、比较正规有含金量的比赛，以中国高等教育学会的竞赛目录为基准。
- **定位**：先作为结课作业完整做出来、能演示；之后可能继续开发上线。

## 2. 角色

| 角色 | 能做什么 |
|---|---|
| 学生 | 填档案和问卷；当队长建队，或者申请加入别人的队；管理自己的日历 |
| 管理员 | 审核身份认证；维护比赛库，确认爬虫抓到的数据；调整问卷和匹配配置；处理举报；看数据看板 |

平台只有学生和管理员两种角色。比赛要求有指导老师的，届次信息里会标出来，老师由同学自己找，平台不管（最初设计过老师发布课题、挂名指导队伍，后来去掉了）。

## 4. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Spring Boot 3 + Java 21 | 本机已有 JDK 21；用 Maven Wrapper，不需要另装 Maven |
| 持久层 | MyBatis-Plus + MySQL 8.0 | 单表增删改查不用手写 SQL，推荐、日历这类复杂查询照样写 XML |
| 登录鉴权 | Sa-Token | 比 Spring Security 好上手，答辩容易讲清楚 |
| 其他 | Spring Mail（验证码）、`@Scheduled`（定时提醒）、Knife4j（接口文档） | |
| 前端 | Vue 3 + Vite + TypeScript + Pinia + Vue Router + Element Plus | |
| 图表、日历 | ECharts（供需缺口图）、FullCalendar（日历视图） | |
| 二期再加 | Redis、WebSocket、OCR、爬虫 | |

老师接受较新的框架，前提是答辩时能讲清楚、能演示。

## 5. 身份认证

**一期：教育邮箱。**

1. 用户填 `xxx@stu.xxx.edu.cn`。
2. 后端检查后缀是 `.edu.cn`，再按 `school_email_domain` 表确定学校。
3. 发 6 位验证码，10 分钟内有效，最多试 5 次，60 秒内不能重发。
4. 验证通过后，账号标记为"已认证"，写入所属学校，有效期到学年末。

一个教育邮箱只能绑一个账号。没认证的用户可以浏览、填问卷，但**不能建队、不能发申请**。

**二期：截图 OCR 预审 + 人工审核。** 上传学信网学籍页截图或学生证照片，OCR 识别出姓名、学校、入学年份，和档案比对后进入审核队列。审核完删除原图，只保留识别出的字段。截图可以 P，所以 OCR 只是减轻审核工作量，不能单独当作证据。

**不用学信网验证码**：学信网没有对第三方开放的核验接口。

## 6. 比赛数据

- **一期**：管理员手动录入，初始数据见 `backend/src/main/resources/db/migration/V2__seed.sql`。
- **二期**（已做）：
  - 爬虫只负责抓各比赛官网的通知原文和链接，遵守 robots.txt；
  - 先用规则从原文里抽出报名起止、比赛时间、人数上下限、是否同校、是否需要指导老师，并记下依据；规则没抽全的再交给大模型补（可选，默认关），每个字段都要有原文依据、对不上的丢掉，网站拒绝 AI 使用的来源不交给大模型；
  - 管理员确认后才入库。
- **加分级别**：由用户标注本校的认定级别并附上学校文件，同校多人确认后才对外显示。

## 7. 日历：图层 + 时间线

- **个人日历**：比赛官方节点、各个队伍的里程碑、个人日程叠成几个图层，每个图层可以单独显示或隐藏。
- **队伍页**：放一条竖向时间线，只列这个队的关键节点，不单独做团队日历页面。
- **数据只存一份**：队长在时间线上加节点，所有队员的日历自动出现。
- **撞期提醒**：个人日程和比赛时段重叠时标红；同时也作为匹配时的一票否决条件。
- **时间不确定的节点**：沿用简程的模型，比如"成绩预计 11 月中下旬公布"。

## 8. 匹配

详见 [问卷草案-v2.md](问卷草案-v2.md)，要点：

- **两级加权**：题目分加权成维度分，五个维度再加权成总分，最后乘承诺系数 K。
- **两类题**：
  - 【两人】题：候选人和每个队员分别比较，取平均；
  - 【团队】题：看候选人加入后队伍的结构，包括技能缺口有没有补上、角色是否分散、有没有人能带新人。
- **按比赛类型换权重**：默认、短期集中型、长周期型三套预设。
- **一票否决只用于客观事实**：撞期、不满足比赛规则、违规记录、目标"冲国一"对"先体验"。
- **配置驱动**：题目和打分配置都存在数据库里，管理员可以在后台调。

## 9. 页面清单

**学生端**

| 页面 | 主要内容 |
|---|---|
| 登录 / 注册 | 邮箱 + 密码，注册时发验证码 |
| 身份认证 | 教育邮箱验证 |
| 首页 | 给我推荐的队伍、近期日程、待处理的申请和邀请 |
| 比赛库 | 列表、筛选；比赛详情（届次、官方节点、关注、这届的队伍） |
| 队伍详情 | 队伍信息、成员、招募需求、时间线；申请加入 |
| 我的队伍 | 编辑招募需求、处理申请、给推荐的人发邀请、管理时间线 |
| 问卷 | 通用部分、比赛级部分、快速版 |
| 日历 | 月视图和周视图、图层开关、撞期提醒 |
| 个人档案 | 资料、技能、履历 |
| 消息中心 | 站内信 |

**管理端**

| 页面 | 主要内容 |
|---|---|
| 认证审核 | 待审核列表 |
| 比赛库管理 | 比赛、届次、节点 |
| 通知抓取 | 爬虫抓到的待确认通知（采用 / 忽略）、抓取来源维护和试抓 |
| 问卷与匹配配置 | 题目、权重、相容矩阵 |
| 数据看板 | 技能供需缺口图（队伍需要的人数 对比 还没组队的人数） |
