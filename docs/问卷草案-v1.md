# 组队匹配问卷 · 草案 v1

> 状态：第一版草案，等你改。题目、选项、权重、相容矩阵都可以调整。

## 设计依据

| 来源 | 借鉴了什么 |
|---|---|
| date-match.online 的匹配配置 | 整体框架：题目 → 维度 → 总分两级加权；四种打分器（slider、single 相容矩阵、ranking、tags）；`hardFilters` 一票否决；开放题不计分、只展示 |
| CATME Team-Maker（高校课程分组工具） | 分组常用的几项标准：课外可用时间、技能（软件、动手、写作）、领导偏好、重细节还是重全局 |
| 数学建模组队经验帖 | 靠谱比高手重要；目标要一致（想加保研分的和只想体验的组在一起，前者会很累）；要看参赛动机；建模、编程、论文三个角色互补；队里需要一个统筹的人；要定期同步进度 |
| 大学生团队"搭便车"研究（Singer 2019，229 名学生） | 半数以上的学生遇到过搭便车。表现分四类：**失联**、**交付质量差**、**开会玩手机**、**讨论不发言**。最强的预测因素是**不投入**；有效的领导能减轻它的影响 |
| Belbin 团队角色 | 9 种团队角色。一个队里"出点子的人"太多会互相顶牛，所以角色要看是否**分散** |

## 和 date-match 的三个区别

1. **加了三种打分器**：互补（技能补缺口）、多样（角色分散）、时段重合（可用时间）。date-match 的打分器都是在比"像不像"，组队很多地方要比"补不补"。
2. **分成两部分**：一部分是个人通用问卷，填一次，以后可以改；另一部分是**每场比赛单独填的参赛意向**（标 `[每场]`），因为同一个人对不同比赛的目标和投入可以完全不同。
3. **人和队伍匹配**：把候选人和队里每个成员分别算一遍，再汇总（规则见文末）。

## 问卷结构

| 维度 | 权重 | 题数 | 关注什么 |
|---|---|---|---|
| A 目标与投入 | 0.25 | 4 | 目标不一致是队伍散掉的头号原因 |
| B 能力与角色 | 0.25 | 4 | 技能互补、团队角色互补 |
| C 协作风格 | 0.20 | 4 | 怎么做决定、怎么推进进度、多久同步一次、怎么处理分歧 |
| D 时间与节奏 | 0.15 | 3 | 能不能凑到一起干活 |
| E 责任与底线 | 0.15 | 3 | 对应"搭便车"的几种表现 |
| F 开放题 | 不计分 | 3 | 推荐时展示给对方看 |

完整版 21 题，大约 6–8 分钟。另外准备一个**快速版**（A1、A3、B2、C2、D1、E1 共 6 题），新用户先填快速版就能拿到推荐，剩下的之后补，提示"补全问卷后推荐更准"。date-match 也有轻量版。

## A 目标与投入（0.25）

### A1 `[每场]` 这场比赛，你的目标是？ · single · 题内权重 0.40

| 选项 | 含义 |
|---|---|
| A | 冲国家级一等奖，愿意为此全力投入 |
| B | 争取省奖或国家级二三等奖 |
| C | 有奖更好，重点是完整做一次 |
| D | 先体验一下，量力而行 |

相容矩阵（对称，行列都是选项）：

|   | A | B | C | D |
|---|---|---|---|---|
| A | 1.0 | 0.6 | 0.2 | **否决** |
| B | 0.6 | 1.0 | 0.7 | 0.3 |
| C | 0.2 | 0.7 | 1.0 | 0.8 |
| D | 否决 | 0.3 | 0.8 | 1.0 |

`hardFilters`：A 和 D 不匹配。

### A2 你参加这类比赛主要为了什么？（最多选 2 项） · tags · 0.10

兴趣，想学东西 / 保研或综测加分 / 简历和求职 / 奖金 / 和朋友一起 / 学院或老师要求

> 权重给得低，主要用来在推荐理由里显示"你们都是为了……"。"学院要求"不做惩罚，只作为参考信息。

### A3 `[每场]` 备赛期间，每周大约能投入多少小时？ · slider 0–30 · 0.35

打分：`s = max(0, 1 − |a − b| / 10)`，也就是相差 10 小时以上记 0 分。

### A4 `[每场]` 冲刺阶段（比如截止前几天、72 小时赛），你能接受的强度是？ · single · 0.15

A 可以通宵 / B 熬到一两点 / C 尽量保持正常作息

相邻两档 0.6，A 和 C 之间 0.2。

## B 能力与角色（0.25）

### B1 技能标签和熟练度 · 读取个人档案，不重复问 · **complement（互补）** · 0.40

和队伍的招募缺口比，不和队员比：

```
缺口 G = {(技能, 要求等级)}，候选人技能 S
s = Σ_g min(S[g], 要求[g]) / 要求[g]  ÷  |G|
```

举例：队伍缺"Vue 2 级、设计 1 级"，候选人会"Vue 3 级"→ s = (1 + 0) / 2 = 0.5。

### B2 `[每场]` 这场比赛你想承担哪块工作？（按意愿排前 2） · ranking + complement · 0.30

选项随比赛类型变，由比赛库的"角色模板"字段配置：
- 数学建模类：建模 / 编程 / 论文写作与排版
- 软件开发类：前端 / 后端 / 算法 / UI 设计 / 产品与答辩
- 创新创业类：技术 / 商业计划书 / 财务 / 路演答辩 / 市场调研

打分：候选人第 1 意愿正好是队伍缺的角色得 1.0，第 2 意愿是得 0.6，都不是得 0。

### B3 在团队里，你更常扮演哪种角色？（选 2 个） · tags · **diversity（多样）** · 0.20

参考 Belbin 的分类，换成大白话：

| 选项 | 对应 Belbin |
|---|---|
| 想点子、提新思路 | 智多星 Plant |
| 定方向、推着大家往前走 | 鞭策者 Shaper |
| 分配任务、协调大家 | 协调者 Coordinator |
| 拿到任务就埋头做完 | 执行者 Implementer |
| 抠细节、检查、收尾 | 完成者 Completer Finisher |
| 找资料、对接老师和外部资源 | 外交家 Resource Investigator |
| 挑毛病、判断方案靠不靠谱 | 审议员 Monitor Evaluator |
| 照顾气氛、调和矛盾 | 凝聚者 Teamworker |

打分：候选人带来的角色里，队里还没有的越多分越高；"定方向"和"想点子"如果和现有队员重复，扣分（容易两个人互相顶）。

```
s = 0.5 + 0.25 × 新增角色数 − 0.25 × 重复的"定方向/想点子"数，限制在 [0, 1]
```

### B4 关于经验，你更希望？ · single · 0.10

A 和经验差不多的人一起 / B 愿意带新人 / C 希望有经验的人带一带

这题不是答案一样就满分：

|   | A | B | C |
|---|---|---|---|
| A | 1.0 | 0.6 | 0.4 |
| B | 0.6 | 0.6 | **1.0** |
| C | 0.4 | **1.0** | 0.2 |

两个人都想被带（C 对 C）只有 0.2。

## C 协作风格（0.20）

### C1 队里有分歧时，你倾向怎么做决定？ · single · 0.25

A 队长拍板 / B 讨论后投票 / C 谁负责的部分谁决定 / D 讨论到大家都同意

> 匹配队伍时，只和**队长**的答案比，因为队伍的决策方式通常由队长定。

相邻两档 0.7，A 和 D 之间 0.3，其余 0.5。

### C2 你推进任务的习惯更接近？ · single · 0.30

| 选项 | 含义 |
|---|---|
| A | 拿到就开始，尽早做完 |
| B | 按计划均匀推进 |
| C | 前期慢慢想，后期集中发力 |
| D | 截止前最有效率 |

|   | A | B | C | D |
|---|---|---|---|---|
| A | 1.0 | 0.8 | 0.4 | 0.1 |
| B | 0.8 | 1.0 | 0.7 | 0.3 |
| C | 0.4 | 0.7 | 1.0 | 0.7 |
| D | 0.1 | 0.3 | 0.7 | 0.8 |

D 对 D 只有 0.8：两个人都拖到最后，风险会叠加。

### C3 你希望队里多久同步一次进度？ · single · 0.20

A 每天 / B 两三天一次 / C 每周一次 / D 有事再说

相邻 0.7，隔一档 0.3，A 和 D 之间 0。

### C4 和队友意见不一致时，你通常会？ · single · 0.25

参考 Thomas-Kilmann 冲突模式的五种类型：

| 选项 | 含义 | 类型 |
|---|---|---|
| A | 坚持到说服对方 | 竞争 |
| B | 拿数据和理由，拉大家一起找最优解 | 协作 |
| C | 各退一步，取个折中 | 妥协 |
| D | 先放一放，回头再说 | 回避 |
| E | 一般听别人的 | 迁就 |

|   | A | B | C | D | E |
|---|---|---|---|---|---|
| A | **0.2** | 0.7 | 0.6 | 0.4 | 0.8 |
| B | 0.7 | 1.0 | 0.9 | 0.6 | 0.8 |
| C | 0.6 | 0.9 | 1.0 | 0.6 | 0.8 |
| D | 0.4 | 0.6 | 0.6 | **0.3** | 0.5 |
| E | 0.8 | 0.8 | 0.8 | 0.5 | 0.6 |

两个都要赢（A 对 A）容易吵起来；两个都回避（D 对 D）问题会越积越多。

## D 时间与节奏（0.15）

### D1 一周里你通常哪些时段有空？ · 7 天 × 3 段（上午 / 下午 / 晚上）勾选 · **overlap（时段重合）** · 0.50

```
s = |A ∩ B| / min(|A|, |B|)，共同空闲少于 3 段时直接记 0
```

和队伍比时，用的是"全队共同有空的时段"。

### D2 你的作息更接近？ · single · 0.25

A 早起型 / B 正常 / C 夜猫子

相邻 0.7，A 和 C 之间 0.3。

### D3 你希望怎么协作？ · single · 0.25

A 线下为主 / B 线上为主 / C 都可以

C 和谁都是 0.9；A 对 B 0.3。另外系统会检查：**如果选了"线下为主"，而两人不在同一所学校**，这一题记 0。

> 不是问卷题：系统会根据个人日历自动检查日程冲突。比赛期间如果和你已经参加的其他比赛重叠，就**直接否决**；如果只是和个人日程重叠，就降低分数，并在推荐理由里提醒。

## E 责任与底线（0.15）

### E1 队友发来消息，你一般多久内会回复？ · slider 0–24 小时 · 0.30

对应搭便车里的"失联"。打分：`s = max(0, 1 − |a − b| / 12)`。

### E2 下面哪些队友行为你最不能接受？（选 3 项并排序） · ranking · 0.40

长时间失联 / 只挂名不干活 / 交的东西敷衍凑数 / 讨论时不发言 / 不打招呼就退队 / 改别人负责的部分不打招呼 / 争署名和排名 / 开会迟到或临时放鸽子

前四项直接对应研究里搭便车的四种表现。打分沿用 date-match 的做法：

```
s = Σ_{两人都选了的项} (1 − |名次a − 名次b| / 3)  ÷ 3
```

> 这道题的答案**还会用于互评**：比赛结束后，队友按这几项互相打分，累积成信用分。

### E3 证书和获奖名单上的署名顺序，你觉得应该怎么定？ · single · 0.30

A 按贡献排 / B 队长排第一，其他人按贡献 / C 比赛前商量好写下来 / D 无所谓

C 和谁都是 0.9，D 和谁都是 0.8；A 对 B 0.5。

> 加这一题是因为：有的学校综测加分会按署名排名区别对待，事后才争很伤队伍。具体规则以各校文件为准。

## F 开放题（不计分，推荐时展示给对方）

- **F1** 我能给队伍带来的三点（比如：熟悉 LaTeX 排版、拿过省奖、执行力强）
- **F2** 希望队友包容我的一个短板（比如：周三全天有课、不太擅长当众讲）
- **F3** `[每场]` 一句话说说你对这场比赛的想法或方向（选填）

F1 和 F2 借鉴 date-match 的"吸引力说明书"和"成长邀请函"。

## 汇总规则

**个人对个人**（个人之间互相推荐时用）：

```
总分 = 100 × Σ 维度权重 × Σ 题内权重 × s(题)
```

先过所有一票否决规则，没通过的直接不进推荐列表。

**个人对队伍**：

| 题目类型 | 和谁比 |
|---|---|
| B1、B2（技能、角色） | 队伍的招募缺口 |
| B3（团队角色） | 全队已有的角色 |
| C1（决策方式） | 只和队长比 |
| D1（可用时段） | 全队共同有空的时段 |
| 其他题 | 和每个队员分别算，取平均 |

一票否决：只要和**任意一个**队员触发否决规则，整个队伍就不推荐。

**推荐理由怎么生成**：
- 把"权重 × 得分"最高的两题套模板，比如"补上了队伍缺的前端（你会 Vue，3 级）""目标一致：都想争取省奖"。
- 得分最低的维度生成一句"组队前先聊聊"，比如"推进习惯不同：你习惯尽早做完，队长习惯截止前集中发力"。

## 存储方式（配置驱动，改题不改代码）

```json
{
  "version": "v1",
  "dimensions": [
    { "key": "goal", "name": "目标与投入", "weight": 0.25, "items": [
      { "q": "A1", "scorer": "single",  "weight": 0.40, "perCompetition": true },
      { "q": "A2", "scorer": "tags",    "weight": 0.10 },
      { "q": "A3", "scorer": "slider",  "weight": 0.35, "perCompetition": true, "tolerance": 10 },
      { "q": "A4", "scorer": "single",  "weight": 0.15, "perCompetition": true }
    ]},
    { "key": "skill", "name": "能力与角色", "weight": 0.25, "items": [
      { "q": "B1", "scorer": "complement", "weight": 0.40, "source": "profile.skills" },
      { "q": "B2", "scorer": "complement", "weight": 0.30, "perCompetition": true },
      { "q": "B3", "scorer": "diversity",  "weight": 0.20 },
      { "q": "B4", "scorer": "single",     "weight": 0.10 }
    ]}
  ],
  "hardFilters": [
    { "q": "A1", "incompatiblePairs": [["A", "D"], ["D", "A"]] },
    { "rule": "competitionTimeConflict" }
  ]
}
```

题目、选项和相容矩阵存在 `survey_question` 表，打分配置存在 `match_config` 表（JSON 字段）。管理员在后台调权重，不用重新部署。
