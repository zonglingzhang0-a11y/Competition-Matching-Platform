## 怎么跑起来

按 [README](../README.md) 操作。几个容易卡住的地方：

- **Windows 用 PowerShell 导入 SQL**：PowerShell 不支持 `<`，`mysql` 一般也不在 PATH 里，用 README 里写全路径、`source` 的那种写法，一次导一个文件。
- **验证码在后端控制台**：开发模式不真的发邮件，注册和教育邮箱的验证码打印在后端窗口里。
- **演示账号**：导入 `sql/demo.sql` 后有 11 个账号，账号、身份和统一密码写在这个文件开头的注释里。
- **后端重启后要重新登录**：登录状态现在存在后端内存里（见下面"已知问题"）。

## 测评指引

建议按下面的顺序测。每一步做完，觉得哪里不对、不好用、看不懂，就在 GitHub 上提一个 Issue。

### 第一版（main）

1. **注册和认证**：注册一个新账号；用 `xxx@stu.example.edu.cn` 认证（自动通过）；再试一个没收录学校的 `.edu.cn` 邮箱（进入待审核）。
2. **比赛库**：筛选、看详情、关注一届比赛。
3. **个人档案**：填资料、技能、履历。
4. **问卷**：先填快速版，再补完整版。
5. **推荐**：用林晓登录看首页和比赛页的"为你推荐"，看推荐理由是否说得通；用陈一舟登录，看"数模冲刺队"页面的"推荐邀请的人"。
6. **组队流程**：申请 → 队长同意或婉拒；队长邀请 → 对方接受；退队、移出、转让队长、解散。
7. **日历**：开关图层；新建一个和比赛时间重叠的个人日程，看撞期提醒；试试每周重复、只删某一次。
8. **站内信**：上面每一步对方是否收到消息，点消息能不能跳到对的页面。
9. **管理后台**（管理员账号）：数据看板、认证审核（吴迪和郑好在等审核）、比赛库管理、匹配配置（改一个权重，回去看推荐分数变没变）、账号停用。

### 二期（dev）

10. **互评**：用赵子航把"国一冲冲冲"标记为比赛结束 → 赵子航和钱多多分别交互评 → 两人都交完后揭晓 → 右上角"互评与信用"看信用分。
11. **信用分对推荐的影响**：用陈一舟看"数模冲刺队"的推荐，周可（往届互评一般）会被降分并提示。
12. **举报**：在别人的队伍页举报 → 管理员在"举报与信用"里处理 → 举报人收到结果。
13. **截图认证**：新注册一个账号 → "身份认证"选"学生证截图"，上传学信网学籍页截图或学生证照片（可以自己画一张假的测试）→ 看识别结果 → 管理员在"认证审核"里看原图和比对结果后通过。

## 已知问题和限制

| 问题 | 影响 | 打算 |
|---|---|---|
| 后端重启后所有人都要重新登录 | 演示前重启要注意 | 二期把登录状态放进 Redis |
| 前端主包超过 500 KB（Element Plus 全量引入） | 首次打开稍慢，打包时有警告 | 改成按需引入 |
| 站内信是每 60 秒查一次 | 新消息最多晚一分钟出现 | 二期做实时推送 |

已经修好的：
- 已认证的人用没收录学校的邮箱重新认证，审核期间会保留原来的认证，驳回也不受影响（以前会变回"待确认"）。
- 队长被停用或暂停推荐后，他的队伍不再推荐给学生；被停用时队伍自动停止招募，待处理的申请作废，队员收到通知。

## 怎么反馈

在 GitHub 仓库的 **Issues** 里新建一个：

- 标题：`【模块】现象`，比如 `【组队】同意申请后队员数没变`。
- 内容：用的哪个分支、哪个账号，怎么操作的（一步一步写），期望的结果，实际的结果，有截图更好。
- 不确定是不是问题的、或者是功能建议，也可以提，标题写 `【建议】`。
