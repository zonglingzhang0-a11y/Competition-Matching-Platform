# 竞赛组队匹配平台

把"谁会什么"和"哪个队缺什么"结构化记录下来，由系统推荐队友并给出推荐理由。面向多所学校的大学生，比赛范围是能在综测里加分的正规竞赛。

**队友请先看 [功能介绍](docs/功能介绍.md) 和 [项目进度](docs/项目进度.md)**：有哪些功能、做到哪了、怎么测、已知问题、接下来做什么。

设计文档在 [docs/](docs/)：[设计方案](docs/设计方案.md)、[问卷 v2](docs/问卷草案-v2.md)、[数据库设计](docs/数据库设计.md)。

## 目录

```
backend/    Spring Boot 4 + MyBatis-Plus + Sa-Token（Java 21）
frontend/   Vue 3 + Vite + TypeScript + Pinia + Element Plus
sql/        schema.sql 建表，seed.sql 初始数据
docs/       设计文档
```

## 环境要求

- JDK 21
- Node.js 24（`^22.18` 或 `>=24.12`）
- MySQL 8.0.16 以上

Maven 不用另外装，`backend` 里自带 Maven Wrapper。

## 第一次运行

**1. 建库**

```bash
mysql -uroot -p < sql/schema.sql
```

```bash
mysql -uroot -p < sql/seed.sql
```

Windows 的 PowerShell 不支持 `<`，而且 `mysql` 一般不在 PATH 里，要写全路径，在项目根目录下用 `source`，一次导一个文件：

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p --default-character-set=utf8mb4 -e "source sql/schema.sql"
```

seed.sql、demo.sql 同理，把文件名换掉即可。

**2. 启动后端**（端口 8090）

把 `backend/src/main/resources/application-local.example.yml` 复制一份，改名为 `application-local.yml`，填上 MySQL 密码。这个文件不会被提交。

想要管理员账号，就在同一个文件的 `app.admin-emails` 里写上你的邮箱：用这个邮箱注册的账号自动成为管理员；如果已经注册过了，重启后端后会自动升级。

```bash
cd backend && ./mvnw spring-boot:run
```

Windows 的 cmd 或 PowerShell 里用 `mvnw.cmd spring-boot:run`。接口文档：<http://localhost:8090/swagger-ui.html>

**3. 启动前端**（端口 5173，`/api` 自动转发到后端）

```bash
cd frontend && npm install && npm run dev
```

打开 <http://localhost:5173>。前端默认把 `/api` 转发到 `localhost:8090`，想连别的后端可以设环境变量 `API_TARGET`。

## 演示数据

想直接看到推荐效果，在 `seed.sql` 之后再导入演示数据：

```bash
mysql -uroot -p < sql/demo.sql
```

导入后会有 11 个演示账号、4 支队伍、问卷答案、一条待处理的入队申请，还有两条等管理员审核的认证申请。账号、身份和统一密码都写在 [sql/demo.sql](sql/demo.sql) 开头的注释里。只用于本地演示，不要导入正式环境。

用 `admin@demo.local` 登录，顶部菜单会多出"管理后台"：

- **数据看板**：账号、队伍、申请的概况；技能供需缺口图（队伍还缺的人数和还在找队的人里会这项技能的人数对比），可以按届次筛选。
- **认证审核**：学校还没收录的教育邮箱在这里排队。确认是哪所学校后通过，平台会收录这个邮箱后缀，同校的其他申请一起自动通过。演示数据里吴迪和郑好就是这种情况。
- **比赛库管理**：比赛、届次（草稿 / 发布 / 归档）、官方时间节点。
- **匹配配置**：维度权重、题目权重、相容矩阵，预设的覆盖项；保存前会检查并试算一次，保存后推荐立刻按新配置计算。
- **账号管理**：停用和恢复账号，停用后对方立刻掉线。
- **举报与信用**：处理举报（暂停推荐、永久不推荐、停用账号、关闭队伍招募），查看被暂停推荐的人和被判为异常的互评。

**互评与信用**（二期）：队长在队伍页点"比赛结束"，录入奖项后队伍归档、队员履历自动记上这场比赛，并开启 7 天的匿名互评。所有人交齐或到期后统一揭晓，结果计入信用分，信用分会乘进推荐时的匹配分。演示数据里陈一舟、孙悦、周可有往届的互评记录：用陈一舟登录，右上角菜单"互评与信用"能看到各项评价；在"数模冲刺队"的推荐里，周可会因为信用分偏低被降分并提示。也可以用赵子航把"国一冲冲冲"标记为比赛结束，再用钱多多交互评，现场演示揭晓。

## 开发时的验证码

默认不真的发邮件，验证码打印在**后端控制台**，像这样：

```
[开发模式] 发往 a@test.local 的注册验证码：582675（10 分钟内有效）
```

想真的发邮件，在 `application-local.yml` 里配置 SMTP，并把 `app.mail.mode` 改成 `smtp`（模板里有 QQ 邮箱的例子）。

**演示教育邮箱认证**：`seed.sql` 里有一所"示例大学"，邮箱后缀是 `stu.example.edu.cn`。随便填一个 `xxx@stu.example.edu.cn`，去后端控制台拿验证码，就能认证成功。填其他学校的 `.edu.cn` 邮箱，会进入"学校待管理员确认"状态。

**截图认证**（没有教育邮箱的同学用）：上传学信网学籍页截图或学生证照片，后端用本地 OCR（RapidOCR）认字，和填写的姓名、学校、入学年份比对后交给管理员审核。

- 不用另外安装 OCR，模型和本地库已经打包进后端（所以后端的包有 70 MB 左右）。
- 本地库是**按打包时的操作系统**选的：在 Windows 上打的包只带 Windows 的库。要部署到 Linux 服务器，就在 Linux 上打包。
- 原图存在后端启动目录下的 `uploads/`（已被 git 忽略），审核完自动删除。可以用 `app.screenshot.upload-dir` 改位置。
