# 竞搭 · 竞赛组队匹配平台

把"谁会什么"和"哪个队缺什么"结构化记录下来，由系统推荐队友并给出推荐理由。面向多所学校的大学生，比赛范围是能在综测里加分的正规竞赛。

**队友请先看 [功能介绍](docs/功能介绍.md) 和 [项目进度](docs/项目进度.md)**：有哪些功能、做到哪了、怎么测、已知问题、接下来做什么。想一起写代码的，再看 [一起开发](CONTRIBUTING.md)：怎么拉分支、提交前跑什么、改了数据库要做什么、PR 怎么提。接手维护的，先看 [项目交接](docs/项目交接.md)：代码在哪、怎么跑、怎么部署、改代码前要知道的坑。

设计文档在 [docs/](docs/)：[设计方案](docs/设计方案.md)、[问卷 v2](docs/问卷草案-v2.md)、[数据库设计](docs/数据库设计.md)。

## 目录

```
backend/    Spring Boot 4 + MyBatis-Plus + Sa-Token（Java 21）
frontend/   Vue 3 + Vite + TypeScript + Pinia + Element Plus
sql/        demo.sql 演示数据，和几个给旧演示库用的小脚本（建表和初始数据在后端的 db/migration 里，启动时自动执行）；技能字典在迁移 V10 里扩到 70 多项
tests/e2e/  接口测试（26 套），sites/ 里是测试用的假官网和假大模型
deploy/     部署到服务器的脚本和配置（见"部署到服务器"）
scripts/    公网演示隧道（public-demo.ps1）、录演示视频（demo-video/）
docs/       设计文档、功能介绍、项目进度、项目交接
```

## 环境要求

- JDK 21
- Node.js 24（`^22.18` 或 `>=24.12`）
- MySQL 8.0.16 以上

Maven 不用另外装，`backend` 里自带 Maven Wrapper。

## 第一次运行

**1. 数据库：不用手工建**

装好 MySQL、记住 root 密码就行。后端第一次启动时会自己建库（`team_match`），再由 Flyway 依次执行
`backend/src/main/resources/db/migration/` 里的迁移文件：V1 建表，V2 填初始数据（技能字典、分工模板、示例学校和比赛、问卷题目和匹配配置），V3 起是之后的改动。执行到哪一步记在库里的 `flyway_schema_history` 表，每次启动只执行还没执行过的。

**已经建过库的（以前手工导入过 schema.sql）**：什么都不用做。第一次用新版本启动时，后端会把这个库记成"已经到 V2"，接着执行 V3"旧库补齐"：以前那几个升级脚本（爬虫、日历订阅、登录保持、邮件提醒、隐私设置）里缺哪个补哪个，已经跑过的跳过，数据不动。这个过程在 v1.0.0 到 v2.2.0 各个版本建的库上都测过（接口测试 `migrate`）。

用过队友那份自带 Flyway 的压缩包启动过的库，迁移记录和这里的对不上，启动会报"checksum mismatch"。这种库换一个库名，或者删掉重建。

**2. 启动后端**（端口 8090）

把 `backend/src/main/resources/application-local.example.yml` 复制一份，改名为 `application-local.yml`，填上 MySQL 密码。这个文件不会被提交。

想要管理员账号，就在同一个文件的 `app.admin-emails` 里写上你的邮箱：用这个邮箱注册的账号自动成为管理员；如果已经注册过了，重启后端后会自动升级。

```bash
cd backend && ./mvnw spring-boot:run
```

Windows 的 cmd 或 PowerShell 里用 `mvnw.cmd spring-boot:run`。接口文档：<http://localhost:8090/swagger-ui.html>

打成 jar 运行时（`./mvnw package`），`application-local.yml` 不会打进 jar（里面有数据库密码，免得 jar 发给别人时带出去）。在 `backend` 目录下这样运行，让它读源码目录里的那份：

```bash
java -jar target/backend-0.0.1-SNAPSHOT.jar --spring.config.additional-location=file:src/main/resources/
```

**3. 启动前端**（端口 5173，`/api` 自动转发到后端）

```bash
cd frontend && npm install && npm run dev
```

打开 <http://localhost:5173>。前端默认把 `/api` 转发到 `localhost:8090`，想连别的后端可以设环境变量 `API_TARGET`。

## 演示数据

想直接看到推荐效果，先让后端启动过一次（表和初始数据就建好了），再导入演示数据：

```bash
mysql -uroot -p < sql/demo.sql
```

Windows 的 PowerShell 不支持 `<`，而且 `mysql` 一般不在 PATH 里，要写全路径，在项目根目录下用 `source`：

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p --default-character-set=utf8mb4 -e "source sql/demo.sql"
```

导入后会有 11 个演示账号、4 支队伍、问卷答案、一条待处理的入队申请，还有两条等管理员审核的认证申请；林晓和陈一舟有几条个人日程（每周的英语课、一条时间说不准的复习计划、一条和国赛撞期的社团换届），资料页上有短板、带证明链接的履历和一个没公开履历的人；示例大学对数学建模的加分认定（A 类）已经确认好，计算机设计大赛的还差一人确认。以前导入过演示数据的，跑一次 `sql/demo-recognition.sql` 补上加分认定的演示内容（可以重复跑）。账号、身份和统一密码都写在 [sql/demo.sql](sql/demo.sql) 开头的注释里。只用于本地演示，不要导入正式环境。

两届示例比赛（"2026 年（示例数据）"）的报名和比赛时间按导入那天往后排：数学建模 9 天后截止报名，计算机设计大赛 35 天后。导入得早、报名已经截止了（建不了队、申请被拦），跑一次下面这个脚本把日期挪到今天附近，不删数据，可以重复跑：

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p --default-character-set=utf8mb4 -e "source sql/demo-refresh-dates.sql"
```

想看铺开的能力雷达（招募需求横跨好几类能力），再跑一次这个脚本，给演示队伍的招募需求多补几项技能要求，可以重复跑：

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p --default-character-set=utf8mb4 -e "source sql/demo-radar.sql"
```

用 `admin@demo.local` 登录，顶部菜单会多出"管理后台"：

- **数据看板**：账号、队伍、申请的概况；**各届组队风险图**（横轴离报名截止几天、纵轴关注了还没进队的人、气泡大小是队伍还差几人，一周内截止还有人没队伍的标红）；**组队漏斗**（关注或在队里 → 填了问卷 → 申请或邀请过 → 进了队 → 队伍组好了，掉人最多的一步标红并写上该做什么）；**推荐准不准**（处理完的申请和邀请按发出时的匹配分每 20 分一段，看每段成了多少；60 分以上不比 60 分以下成得多，就提示去「匹配配置」调权重。匹配分平时不存，从 V9 起在发申请、邀请的那一刻记下来，之前的老记录不算）；**运营**（四小块，每块写清楚该做什么：申请和邀请有几条等了 3 天以上、压在谁手上；认证审核按学校分、没收录的邮箱后缀单独标出；每个爬虫来源正常、出错还是好几天没抓；举报待处理多久、暂停推荐几个人）；技能供需缺口图（队伍还缺的人数和还在找队的人里会这项技能的人数对比）。点气泡或届次表的一行，漏斗和缺口图一起切到那一届。
- **认证审核**：学校还没收录的教育邮箱在这里排队。确认是哪所学校后通过，平台会收录这个邮箱后缀，同校的其他申请一起自动通过。演示数据里吴迪和郑好就是这种情况。
- **比赛库管理**：比赛、届次（草稿 / 发布 / 归档）、官方时间节点。
- **通知抓取**：爬虫抓到的比赛通知，核对原文后采用，生成一届草稿或更新已有的一届（见下面的[比赛通知爬虫](#比赛通知爬虫)）。
- **匹配配置**：维度权重、题目权重、相容矩阵，预设的覆盖项；保存前会检查并试算一次，保存后推荐立刻按新配置计算。
- **账号管理**：停用和恢复账号，停用后对方立刻掉线。
- **举报与信用**：处理举报（暂停推荐、永久不推荐、停用账号、关闭队伍招募），查看被暂停推荐的人和被判为异常的互评。
- **加分认定**：同学们标注的各校认定级别，同校有分歧的标出来，乱填的可以驳回（见下面的[各校加分认定](#各校加分认定)）。

**互评与信用**（二期）：队长在队伍页点"比赛结束"，录入奖项后队伍归档、队员履历自动记上这场比赛，并开启 7 天的匿名互评。所有人交齐或到期后统一揭晓，结果计入信用分，信用分会乘进推荐时的匹配分。演示数据里陈一舟、孙悦、周可有往届的互评记录：用陈一舟登录，右上角菜单"互评与信用"能看到各项评价；在"数模冲刺队"的推荐里，周可会因为信用分偏低被降分并提示。也可以用赵子航把"国一冲冲冲"标记为比赛结束，再用钱多多交互评，现场演示揭晓。

## 公网演示（发一个链接，别人在任何网络下都能打开）

在校园网里，别人的电脑往往连不上你的电脑。双击项目根目录的 `public-demo.bat`：它启动后端、打包并启动前端，再开一条 Cloudflare 临时隧道，最后打印一个 `https://xxx.trycloudflare.com` 网址，发给别人就能打开你电脑上的网站。思路来自队友的 `start-demo.bat`，改成了不写死本机路径的版本（脚本在 `scripts/public-demo.ps1`）。

- 要先自己下载 cloudflared：在 [cloudflared 的发布页](https://github.com/cloudflare/cloudflared/releases) 下载 `cloudflared-windows-amd64.exe`，改名为 `cloudflared.exe` 放进项目里的 `tools` 文件夹（已被 git 忽略），或者用环境变量 `CLOUDFLARED` 指向它。
- 还要 MySQL 在运行、`application-local.yml` 填好了密码；数据库不用手工建。想让别人看到推荐效果，先导入演示数据。
- 电脑要一直开着、不能休眠，脚本打开的几个窗口都别关；网址每次运行都不一样。
- **拿到网址的人都能登录演示账号、改数据**，只发给信得过的人。
- 现在验证码只打印在后端窗口里、不发邮件，别人没法自己注册新账号，请让他们用演示账号。
- 前端改过代码后，运行 `public-demo.bat -Rebuild` 重新打包。
- 隧道里浏览器的域名是 `*.trycloudflare.com`，后端看到的是 `localhost`，新消息推送默认会被来源检查拦下来；脚本启动后端时加了 `--app.push.allowed-origin-patterns[0]=https://*.trycloudflare.com` 放行。后端如果是你自己另外启动的，推送会退回每分钟查一次，别的功能不受影响。

## 部署到服务器

正式的网站部署在阿里云：<http://47.111.123.178>（队友部署和维护）。脚本和说明都在 [deploy](deploy) 文件夹，服务器上后端、配置、前端、备份各在哪见 [deploy/README.md](deploy/README.md)。

- 服务器只认密钥登录：自己生成一对密钥（`ssh-keygen -t ed25519`），把**公钥**发给管服务器的队友加上。
- 部署：先把本机切到要发布的分支、拉到最新，确认没有没提交的改动（脚本会把工作区里的代码原样传上去），然后在 **Git Bash** 里运行 `KEY=~/.ssh/你的私钥 bash deploy/deploy.sh`。前端在本机打包；后端把源码传到服务器上打包，因为 OCR 的本地库按打包时的系统选，Windows 上打的包在 Linux 上用不了。
- 服务器上的 `/opt/jingda/application-local.yml` 是服务器专用的配置（数据库账号、发信邮箱等），不要用本机的覆盖。
- 每次部署后端重启时，Flyway 会自动升级表结构；数据库每天凌晨 4 点自动备份，留 7 天。

## 开发时的验证码

默认不真的发邮件，验证码打印在**后端控制台**，像这样：

```
[开发模式] 发往 a@test.local 的注册验证码：582675（10 分钟内有效）
```

想真的发邮件，在 `application-local.yml` 里配置 SMTP，并把 `app.mail.mode` 改成 `smtp`（模板里有 QQ 邮箱的例子）。

验证码有发送上限，免得有人换着邮箱一直点、把发信邮箱一天的额度刷光：同一个邮箱 60 秒一封；同一个 IP 一小时最多 30 封、24 小时最多 100 封；全站一天最多 300 封。三个数在 `app.code` 里改（`ip-per-hour`、`ip-per-day`、`total-per-day`）。全班用同一个校园网一起注册时，大家共用一个出口 IP，每人还要发注册和学校认证两封，记得先把 `ip-per-hour` 调大。部署在 Nginx 后面时，Nginx 要设 `X-Real-IP`，不然所有人都算成同一个 IP。

**演示教育邮箱认证**：初始数据里有一所"示例大学"，邮箱后缀是 `stu.example.edu.cn`。随便填一个 `xxx@stu.example.edu.cn`，去后端控制台拿验证码，就能认证成功。填其他学校的 `.edu.cn` 邮箱，会进入"学校待管理员确认"状态。

**截图认证**（没有教育邮箱的同学用）：上传学信网学籍页截图或学生证照片，后端用本地 OCR（RapidOCR）认字，和填写的姓名、学校、入学年份比对后交给管理员审核。

- 不用另外安装 OCR，模型和本地库已经打包进后端（所以后端的包有 70 MB 左右）。
- 本地库是**按打包时的操作系统**选的：在 Windows 上打的包只带 Windows 的库。要部署到 Linux 服务器，就在 Linux 上打包。
- 原图存在后端启动目录下的 `uploads/`（已被 git 忽略），审核完自动删除。可以用 `app.screenshot.upload-dir` 改位置。

## 我的主页、一句话添加和日历订阅

登录后的主页按"左边赛程、中间比赛、右边组队"排，三栏一样宽。右上角「自定义主页」可以隐藏面板、在同一栏里上下调顺序、把日历栏加宽（「待你处理」不能隐藏，免得错过邀请），改了马上生效，存在账号里，换台电脑登录也一样；一整栏都隐藏了，剩下的栏自动变宽。日历右上角的「加宽」和这里的开关是同一个设置。三栏的比例在 `HomeView.vue` 的 `.grid` 里，改那几个变量就行。

- 顶部一句话说今天有没有截止，旁边是下一个节点（进度环）、之后的两个节点、本周可投入几小时（按问卷勾的空闲时段扣掉日程估算）。
- 左栏是赛程日历（周 / 月）和学期赛程带：月视图只画记号不写字——参加的比赛期间是黑色细线、关注的是虚线，截止日是红色菱形，队伍节点是黑色菱形，个人日程是小圆点，撞期的带红色；鼠标放到某一天上（手机上点一下）弹出当天的详情，点条目跳到比赛或队伍。周视图照旧写出标题。下面一排是每周空闲，一周里截止 ≥ 2 个、空闲 < 6 小时会提前给出冲突预警。
- 中栏是我参加的比赛（阶段进度、队员、下一个截止）和正在报名、适合你的比赛；右栏是待你处理的邀请和申请（接受前提示影响，比如"接受后 10 月会有 3 个比赛同时进行"）、推荐队友或队伍、最近消息。
- **匹配六边形**（右栏推荐队友 / 推荐队伍上方）：匹配引擎的 5 个打分维度（目标与投入、能力与角色、协作风格、时间与节奏、责任与底线）加上投入保障（互评信用和备赛期间的考试、实习算出来的承诺系数）。点下面的人或队伍换着看，"叠上去对比"再选一个画成虚线框。没数据的维度画在 50 分、空心点、灰字"没数据"（不画成 0 分）；问卷没填全的整个六边形是虚线，写"仅供参考"。总分是五项加权后乘投入保障，不是六项的平均。

**一句话添加**：主页赛程日历和日历页上方的输入框，直接写"明天下午3点到5点 队伍开会""周五前交论文初稿""每周六上午9点到12点 数模集训 到11月30日"，边打字边显示认出来的日期、时间和重复，回车就加进个人日程；认得不对点"细调"，在完整表单里改。认得出今天明天、周几、下周几、几月几号、几天后、日期段，几点到几点（中文数字也行）、过午夜，时长，每天、工作日、每周几、每个周末和重复到哪天，还有说不准的起止（"下个月找时间开始""大概两周""月底前做完""做完为止"）；剩下的文字当标题。解析在前端完成，规则改自作者自己的日程应用"简程"。

**时间说不准的日程**：新建日程时打开"说不准"，可以填最晚哪天开始，结束选确定、一个范围（最早到最晚）或者做完为止。日历上画成虚线框，显示到最晚那天。这类日程不能重复，也不参与撞期检测和每周空闲估算，免得"大概两周"把整段时间都标成冲突。

**订阅到手机日历**：主页或日历页点"订阅到手机日历"，拿到一条私有链接（iCalendar 格式），手机和电脑自带的日历订阅后会定时同步比赛节点、队伍节点和个人日程，截止提前一天提醒。链接里带着密钥，相当于密码，泄露了可以重置。手机要能访问到服务器才能订阅，本机运行时可以先下载 .ics 导入电脑日历。

界面风格参考了 [RhineLabUI](https://github.com/LBEILC/RhineLabUI)（MIT）的配色和排版，字体用 MiSans（小米，免费商用），从 jsDelivr 按需加载，连不上时退回系统字体。

## 站内信实时推送和邮件提醒

登录后，浏览器和后端保持一条 WebSocket 连接（`/api/ws/notifications`）。有新消息时，后端在业务提交后马上推过来：铃铛数字立刻更新，右上角弹出提示，点提示跳到相关页面。一个页面标了已读，同一个人开着的其他页面也跟着变。连不上时自动退回每分钟查一次，并按 2、5、10、30、60 秒的间隔重连。

- 建连接用一次性票：前端先用登录令牌换一张票（30 秒内有效，只能用一次），登录令牌不会出现在网址里。连接期间每 30 秒心跳一次，顺便检查登录是否还有效，退出登录或被停用后连接会被关掉。
- 开发时 Vite 的 `/api` 转发已经带上了 WebSocket，不用另外配置。部署到服务器时，反向代理要给 `/api/ws/` 打开 WebSocket，并把 Host 原样传给后端（后端只接受同域名的页面连接），Nginx 的写法：

```nginx
location /api/ws/ {
    proxy_pass http://127.0.0.1:8090;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 120s;
}
```

- 连接和票都存在后端内存里，只支持一台服务器；以后多台部署要用 Redis 在服务器之间转发。

**邮件提醒**：不在网站上的人，新消息超过 10 分钟没看，后端把这几条汇总成一封邮件发到注册邮箱（每 5 分钟检查一次）。这段时间里在网站上看过了、或者正开着网站，就不发；每条消息最多发一次，"有队员退出"这类只是告知的不发。每个人可以在消息页关掉"邮件提醒"。开发模式（`app.mail.mode: log`）下邮件打印在后端控制台；配好 SMTP 后真的发，部署时把 `app.notify-mail.site-url` 改成网站的真实地址（邮件里的链接用它）。时间都在 `application.yml` 的 `app.notify-mail` 里改。

## 各校加分认定

同一个比赛，各校综测怎么认定（A 类、一类竞赛、加几分）不一样，平台不去爬各校的文件，而是让同校同学来标：认证过的同学在比赛页"加分认定"里填本校的认定级别、说明和学校文件链接，另外 2 位同校同学点"我也确认"后，这条才在比赛页、比赛列表、主页和自己档案页的参赛履历上显示（"本校 A 类"这样的标签）。其他学校已经确认好的也会列出来。

- 每人对一个比赛只算一种说法：确认了别人的，就不能再自己提交；改确认另一条，原来的确认自动撤掉。
- 改了级别或文件链接，等于换了一种说法，之前的确认清零；只改说明不影响。
- 同校有几条都确认够了，显示确认人数最多的那条；不显示是谁提交、谁确认的。
- 管理后台"加分认定"能看到全部标注，同校有分歧的会标出来，乱填的可以驳回（提交的人会收到原因）。
- 要几个人确认在 `application.yml` 的 `app.recognition.confirms-needed` 里改。用的是 v1 就建好的两张表，不用跑升级脚本。

## 比赛通知爬虫

后端每天早上 7:30 抓一次各比赛官网的新通知（管理后台"通知抓取"里也能手动抓），用规则抽出报名起止、比赛时间、每队人数、是否必须同校、是否必须有指导老师，并记下每个字段是从哪句话里抽的。抓到的通知只进待确认列表，管理员核对原文后"采用"，才会生成一届草稿（或更新已有的一届）和官方时间节点。

- 预置了数模、电赛、计设三个官网的抓取来源（初始数据 `V2__seed.sql`）。来源在后台维护：列表页网址、通知链接的 CSS 选择器、标题关键词和排除词、正文的选择器。写好后点"试抓"，能看到列表里每个链接会不会被抓、为什么。
- 守规矩：先看网站的 robots.txt，不让抓的不抓；同一网站两次请求至少隔 2 秒；每个来源一次最多打开 10 篇新通知；抓过的链接不再打开；附件（PDF、Word 等）不下载。User-Agent 里写了本仓库的地址。
- 往年的、时间都已经过去的通知会自动忽略，记录还留着，管理员觉得判断错了可以改为采用。
- 字段先用规则抽。写在附件里的内容抽不到，要打开原文手动填。
- **大模型补抽（可选，默认关）**：规则没抽全报名截止、比赛时间、人数的通知，可以再交给大模型补（OpenAI 兼容接口，本机的小模型或 DeepSeek 这类云端模型都行）。在 `application-local.yml` 里打开：

  ```yaml
  app:
    llm:                                 # 大模型连接，爬虫补抽、比赛页 AI 整理、AI 能力分析共用（以前叫 app.crawler.llm）
      enabled: true
      base-url: http://127.0.0.1:8096/v1   # 云端的话换成它的地址，再填 model 和 api-key
  ```

  本机模型一次只处理一个请求，几个功能同时要用时排队，最多等 20 秒（`app.llm.wait-ms`），等不到就当这次没连上、各自退回规则。

  规则抽到的字段不会被换掉，大模型只补缺的。每个字段都要带上原文里的一句话当依据，这句话在原文里找不到、或者句子里没有它给的日期和人数，就不要这个字段，防止大模型编造。确认页面里大模型补的依据会标"大模型"。没配、连不上、超时都只用规则，不影响抓取和启动。
- 在 robots.txt 里拒绝 AI 爬虫的网站（抓取时会自动标出来）始终只用规则，不交给大模型。挑战杯官网就是这种情况，所以默认停用。
- 不想定时抓（比如在本地开发），在 `application-local.yml` 里设 `app.crawler.enabled: false`，手动抓不受影响。

### 比赛页的「AI 帮我整理」

比赛页标题旁的按钮，点了从右边滑出一个抽屉：

- 顶上提醒"AI 整理的，可能不全、可能过时，以官网和学校通知为准"。
- **要点**：把平台抓到的这个比赛最近几篇官方通知（最多 4 篇）交给大模型，按报名时间、比赛时间、参赛对象、组队要求、报名方式、提交作品、赛程安排、奖项设置、费用、其他注意事项整理，最多 8 条。每条都要带上通知里的一句原话，点"看原文"能看到这句话和出自哪篇通知。原话在通知里找不到、或者要点里的日期数字原话里没有，这条就丢掉。
- 报名时间、比赛时间、组队要求没整理出来的，单独提醒去别的渠道查。
- **更多信息渠道**：比赛官网、各届的官方通知、平台抓通知的列表页（同一个网址只列一次），再加上按自己和平台数据写实的四条：
  - 本校教务处、学院的通知：写上自己的学校，点开直接搜"学校 + 比赛 + 校赛 通知"（没认证学校的搜比赛名）；
  - 官方微信公众号：写出比赛全称，一键复制去微信里搜；
  - 平台上参加过往届的同学：几个人参加完了往届、其中本校几个，"去看看"跳到本页往届的队伍；还没有记录时提示问问身边参加过的人；
  - 本页的加分认定：直接写出本校同学确认过的级别（或者还没人确认），"去看看"跳到加分认定那一块。
- **平台抓到的通知**：列出最近的几篇，标出哪些用于这次整理；来源网站不让 AI 读的只放链接，从不交给大模型。

本机算力有限，**只有管理员能点"整理 / 重新整理"真的调大模型**（要先按上面打开 `app.llm`），同一时间只整理一个比赛，结果存起来。学生打开抽屉不调大模型，而是把存好的结果一步步放出来（每一步说的都是这份总结实际做过的事，顶上写着整理时间和模型）。大模型这次的回答一条都对不上原文时报错，原来的总结不动。表是迁移 `V7__competition_ai_summary.sql` 建的。

## AI 能力分析和招募建议（可选，默认关；队友写的）

注册时只填邮箱，还没有"特长、经历、性格"可分析；真正的信号来自档案（技能、简介、履历）和组队问卷，所以入口在"我的档案"：

- **个人**：填完快速问卷（7 题）和技能后，点"AI 能力分析"，会读技能、履历、简介和问卷里合作相关的题，给出总结、优势、合作风格、建议补的技能（每条带资料原话）。建议的技能要自己勾选、调熟练度、点"加入我的技能"才会写进档案，雷达图随后更新。
- **队伍**：队长在队伍页点"AI 招募建议"，会结合队员的技能、雷达、问卷特点和还开着的需求，给出最缺的能力、该找什么样的人、组队前问什么。需求技能的差距是后端算的，模型只解释。

大模型和爬虫补抽、比赛页 AI 整理共用一份连接配置（`app.llm`，见"比赛通知爬虫"一节）。AI 能力分析会把档案内容发给模型，所以另外有一个开关，两个都打开才会调模型：

```yaml
app:
  llm:
    enabled: true
    base-url: http://127.0.0.1:8096/v1   # 云端的话换成它的地址，再填 model 和 api-key
  ai:
    enabled: true                        # 允许把档案发给模型做分析
    cooldown-seconds: 60                 # 同一个人 / 同一支队两次分析的间隔
```

- **没配或连不上会降级**：自动用本地规则算（技能 + 问卷 + 需求雷达），页面上标"本地规则"，不会假装是 AI；配置好后点"重新分析"即可换成模型结果。本机模型一次只处理一个请求，正忙的时候也退回本地规则。
- **防编造**：模型给的每条优势、性格、技能都要带资料里的原话，找不到就丢掉；技能名必须在技能字典里，等级只能是 1–3。
- **隐私**：只发技能、履历、专业和合作相关的问卷题；邮箱、联系方式、真实姓名、完整问卷答案都不发。个人分析是本人点的，招募建议只有队长能看。
- **成本**：结果存在 `ai_analysis` 表里（迁移 `V11__ai_analysis.sql`），打开页面不重复请求；同一人/队 60 秒内重复点会直接用上次结果。
